# KFC TUI Markdown 与问答分隔设计

- **状态：** Accepted
- **决定日期：** 2026-08-01

## 背景

模型最终回答通常包含 Markdown，但当前 Workbench 只净化终端控制序列，随后把整段文本按普通字符串展示。标题、列表、强调和代码块因此失去层次；连续多轮问答也缺少明确的视觉边界。

## 决定

1. 增加一个无副作用的 Markdown 投影器，仅转换 TUI 展示行，不修改 Agent 消息或 Provider 数据。
2. 首版支持标题、无序/有序列表、引用、行内代码、粗体/斜体和 fenced code；未知语法保留为安全纯文本。
3. fenced code 使用 `┌─`、`│`、`└─` 结构显示，流式增量尚未收到闭合 fence 时不补造内容。
4. 每个非首轮用户消息前渲染低亮度分割线；`NO_COLOR` 下保留分割线字符但不输出 ANSI。
5. 所有动态文本先经过既有终端净化；ANSI 只由静态主题 token 生成。

## 代价与边界

- 不实现完整 CommonMark、表格布局、链接跳转或语法高亮；这些能力会增加终端宽度、流式增量和安全边界复杂度。
- 当前截断仍按终端适配器的安全单元处理，后续若需要 Unicode 宽度精确布局，再独立升级渲染器。
