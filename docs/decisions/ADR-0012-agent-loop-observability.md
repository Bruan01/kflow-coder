# ADR-0012：无限 Agent Loop 的无进展检测与运行观测

- 状态：Accepted
- 日期：2026-08-01
- 范围：Agent Core、CLI、Interactive TUI

## 背景

固定步数不能判断编程任务是否完成，但完全没有无进展保护也不可靠。模型可能反复请求同一个工具，
而工具每次返回相同结果；此时继续增加模型轮次只会消耗 Token，并把“系统正在工作”的假象延长。
另一方面，只有最终文本而没有运行指标，用户无法判断长任务到底执行了多少模型轮次、工具动作和 Token。

## 决策

1. 生产 Agent 继续使用 `maxSteps: "unlimited"`，不恢复总步数上限。
2. Agent Core 记录最近完成的工具轮次指纹。指纹只包含工具名称、输入、结果内容和 `isError`，不包含 Provider 生成的 Tool Call ID。
3. 连续三轮工具请求和安全结果完全相同，抛出 `AGENT_REPEATED_TOOL_CALL`。不同请求、不同结果或用户中断都会打破连续计数。
4. 成功的 `AgentRunResult` 返回 `metrics`：模型轮数、工具调用数、失败工具调用数、总耗时、首字延迟、峰值单轮输入 Token 和累计 usage。
5. CLI Agent 统计输出到 stderr；TUI `/status` 输出相同事实。成本在没有模型价格表时显示“未知”，不进行伪精确估算。

## 不变量

- 重复检测不是任务总长度限制；不同工作可以无限继续。
- 指纹不展示工具输入和结果，避免把文件内容或敏感数据写入错误信息。
- 统计值只来自 Provider usage、Agent 实际事件和本地计时，不由 UI 估算模型 Token。
- `AgentRunResult.metrics` 对新 Core 运行始终产生；旧嵌入式调用返回的兼容结果可以没有该字段，CLI 仍能安全降级。

## 代价与后续

- 三轮阈值是保守的安全边界，某些确实需要重复读取的任务可能提前停止；用户可以修正工具状态或调整请求后重试。
- 当前没有模型价格表，因此只能观测 Token，不能报告可靠成本。
- P4 仍需把模型、工具、权限和完成状态统一为领域事件，并以 JSONL 保存完整会话轨迹。
