# ADR-0010：只读 Git 变更摘要与失败恢复说明

- 状态：Accepted（P3.1）
- 日期：2026-08-01
- 范围：工作区 Tool Registry、交互式 Workbench

## 背景

KFC 已经能够在用户授权后修改文件或执行 Shell，但“执行成功”不等于“用户知道工作区发生了什么”。
如果工作区在会话开始前已经有未提交或未跟踪内容，简单地展示当前 `git diff` 还会把旧状态误报为本轮产物。
工具失败时也不能通过自动 `reset --hard` 或删除文件来“恢复”，因为那会把用户原有工作丢失。

## 决策

1. 增加只读 `git_diff` 工具，固定调用 `git status`、`git diff --numstat` 和必要的 `git diff --no-index`，
   全部使用参数数组执行，不经过 Shell。
2. 创建工作区工具时记录一次会话基线。结果按文件报告：状态、暂存/未暂存、增删行数、未跟踪状态、
   `preexisting` 和 `newSinceSession`。工具不返回完整 patch 内容。
3. 编辑工具成功结果标记 `workspaceChange: changed`；Shell 结果标记 `unknown`，因为任意命令都可能触碰工作区。
   失败结果只说明可观察事实和恢复路径，不猜测不存在的回滚点。
4. 交互终端在一轮失败后展示已完成工具、失败工具、工作区状态和恢复提示；不自动执行 reset、checkout、
   clean、删除或其他破坏性操作。

## 保持的不变量

- `git_diff` 不改变工作区，不提交，不回滚，不切换分支。
- 会话前已有的脏状态必须能够与本轮新增状态区分。
- 未跟踪文件也必须进入摘要；不能只依赖 `git diff`（它默认忽略未跟踪文件）。
- 失败说明必须包含“是否确认改变”“哪些操作已完成/失败”“下一步如何安全检查”。
- 工具结果仍然是结构化 JSON；UI 只投影白名单摘要，不显示完整文件内容和 Shell 原始输出。

## 代价与未解决问题

- 基线只在当前进程会话内有效，重启后不会跨会话追踪。
- Shell 的工作区影响仍只能标记为未知，必须再次运行 `git_diff` 才能确认。
- 目前不提供自动回滚、patch 反向应用、提交或分支管理；这些属于更高风险的后续阶段。
- Git 不存在或当前目录不是仓库时，工具返回安全错误，而不是把 Git 错误栈泄露给模型或用户。

## 验收

- 临时 Git 仓库测试覆盖已跟踪修改、未跟踪文件、会话前脏文件和非 Git 目录。
- 交互终端测试覆盖“修改结果已产生后本轮失败”的恢复说明。
- `pnpm build`、`pnpm typecheck:tests`、源码 ESLint、相关 Vitest 和 `git diff --check` 必须通过。
